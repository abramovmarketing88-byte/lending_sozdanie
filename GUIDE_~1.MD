## ШАГ 0 — Подготовка папки проекта

Перед началом попроси Claude выбрать рабочую папку:

```
Выбери папку для проекта на моём компьютере, 
куда будешь сохранять все файлы.
```

Структура, которую получишь в итоге:
```
/мой-проект
  spec.md          ← техзадание (Шаг 2)
  research.md      ← исследование конкурентов (Шаг 3)
  index.html       ← готовый лендинг (Шаг 5)
  /bot
    bot.py
    .env           ← токен бота (не в git!)
    README.md      ← инструкция для новичка
```

## ШАГ 2 — Discovery Interview → spec.md

**Когда:** Перед любой работой над продуктом  
**Что делает:** Превращает расплывчатую идею в чёткое техзадание (12+ разделов)

### Промт:

```
РОЛЬ: Ты — маркетолог-аналитик с навыком Discovery Interview.
Задача — превратить мою расплывчатую идею в техзадание.

ДЕЙСТВИЕ:
1. Задавай вопросы по одному (не списком)
2. Сначала маркетинг: ЦА, цель, конкуренты, ценность
3. Технические вопросы — только после маркетинговых
4. В конце создай файл spec.md минимум с 12 разделами:
   - Контекст и цель
   - Метрики успеха
   - Целевая аудитория
   - Дизайн-система
   - Структура страницы
   - Текстовый стиль
   - Технический стек
   - Безопасность
   - Чек-лист готовности

Моя идея: [опиши здесь свою идею]
```

**Ожидаемый результат:** файл `spec.md` в папке проекта

## ШАГ 3 — Параллельное исследование → research.md

**Когда:** После создания spec.md  
**Что делает:** 3 параллельных поиска — западные проекты, российские, фишки конверсии

### Промт:

```
РОЛЬ: Ты — исследователь-аналитик.
КОНТЕКСТ: Я делаю [тип продукта] для [бизнес-задача].

ДЕЙСТВИЕ:
1. Запусти 3 параллельных поиска:
   — Поиск 1: западные премиум-проекты по теме
   — Поиск 2: российские топовые проекты
   — Поиск 3: фишки конверсии и вовлечения в нише

2. Сведи всё в один файл research.md:
   — Топ-5 проектов с прямыми ссылками
   — Структура страницы у каждого (по разделам)
   — Дизайн: палитра, типографика, впечатление
   — Механики вовлечения (квизы, всплывашки, геймификация)
   — «5 главных фишек, которые забираем к себе» с обоснованием

Тема: [твоя тема]
```

**Ожидаемый результат:** файл `research.md` в папке проекта

## ШАГ 4 — Plan Mode → план из 15–20 этапов

**Когда:** После того как spec.md и research.md готовы  
**Как активировать:** нажми **Shift + Tab дважды** (или кнопку Plan Mode внизу интерфейса)

### Промт:

```
РОЛЬ: Ты — старший разработчик. Plan Mode включён.
КОНТЕКСТ: В папке лежат spec.md и research.md.
Пока не покажешь план и я не одобрю — код не пишем.

ДЕЙСТВИЕ:
1. Прочитай оба файла
2. Найди расхождения между ТЗ и исследованием
3. Предложи обновить spec.md если нужно — жди согласия
4. Составь план: 15–20 шагов
   Каждый шаг: что делаем / какие файлы / как проверим
5. После плана — список рисков и ожидаемых решений

ФОРМАТ: Нумерованный список, у каждого пункта — критерий приёмки.
Когда план готов — жди одобрения, ничего не пиши в код.
```

> ⚠️ Не одобряй план пока не убедишься что все шаги логичны.  
> После одобрения — выйди из Plan Mode (снова Shift+Tab или кнопка).

**Ожидаемый результат:** утверждённый план в чате, обновлённый spec.md

## ШАГ 5 — Лендинг → index.html

**Когда:** После одобрения плана  
**Скилл:** `ui-ux-pro-max` (уже установлен)

### Промт:

```
РОЛЬ: Ты — старший фронтенд-разработчик и дизайнер.
Используй скилл ui-ux-pro-max для этой задачи.
КОНТЕКСТ: План одобрен. В папке лежат spec.md и research.md.

ДЕЙСТВИЕ:
1. Создай лендинг по плану
2. Технологии: один файл index.html со встроенными стилями.
   Открывается в браузере двойным кликом, без установок
3. Дизайн: выбери направление по spec.md и research.md:
   минимализм / премиум / ретро-футуризм
4. Структура:
   главный экран → 3 выгоды → отзывы → квиз → форма заявки → CTA
5. Шрифты — из Google Fonts. Не дефолтные системные
6. Палитра — 2–3 цвета, один акцентный
7. Анимации — плавные, на скролле и при наведении

ФОРМАТ: Один файл index.html. 
После создания проверь что рендерится без ошибок.
В конце скажи что сделано и что проверить.

Работай.
```

### Как давать правки (только точечные):
✅ «Главный экран сделай светлее, шрифт крупнее»  
✅ «Переделай секцию отзывов в стиле минимализм, остальное оставь»  
✅ Вставить скриншот референса — Claude проанализирует стиль  
❌ «Переделай» без уточнений — это запустит всё с нуля

**Ожидаемый результат:** файл `index.html` в папке проекта

## ШАГ 6 — Telegram-бот → папка bot/

**Когда:** После готового лендинга

### Подготовка (нужно сделать вручную):
1. Открой Telegram → найди **@BotFather** → напиши `/newbot`
2. Придумай имя (например: "Мой Магазин") и ник (обязательно на `_bot`)
3. Скопируй токен — выглядит так: `123456789:ABCdefGhIjKlmNoPQRsTuVwXyZ`
4. Свой Telegram ID: найди **@userinfobot** → напиши `/start` → сохрани цифры

### Промт:

```
РОЛЬ: Ты — backend-разработчик.
КОНТЕКСТ: Лендинг создан. Бот дополняет воронку —
ловит клики, проводит диалог, квалифицирует, отдаёт заявку менеджеру.
В папке лежит spec.md — аудитория, услуги, стиль общения. Используй.

ДЕЙСТВИЕ:
1. Создай папку bot внутри проекта
2. Технологии: Python + python-telegram-bot (самое стабильное)
3. Сценарий бота:
   /start → приветствие + меню (3–4 кнопки)
   → пользователь выбирает услугу → бот спрашивает задачу
   → бот спрашивает бюджет (диапазоны кнопками)
   → бот спрашивает дату/срок
   → бот собирает имя и контакт
   → шлёт уведомление с готовой заявкой менеджеру
4. Токен: [ВСТАВЬ СЮДА ТОКЕН] — спрячь в .env, не хардкодь
5. Мой Telegram ID: [ВСТАВЬ СЮДА ID]
6. После сборки покажи команду запуска

ФОРМАТ: Все файлы в папке bot/
README.md с пошаговой инструкцией запуска для новичка.

Работай.
```

> ⚠️ Если засветил токен случайно: `@BotFather → /revoke → подтвердить → новый ключ в .env`

**Ожидаемый результат:** папка `bot/` с bot.py, .env, README.md

## 💡 Полезные подсказки

### Память между сессиями (consolidate-memory)
Если проект длится несколько дней — попроси Claude сохранить контекст:
```
Сохрани ключевые факты о проекте в память, 
чтобы я мог продолжить в следующей сессии.

Откати последнее изменение и объясни что произошло.
```

```
Проведи SEO-аудит index.html. 
Оптимизируй мета-теги, заголовки, скорость загрузки.
```
